# CHANGELOG

リリースごとに 1 ファイル。**ストアにそのまま貼る文章**と、**あとで追うための記録**を
同じファイルに置く。

- ファイル名は `<バージョン>.md`。パッチ番号が 0 でも省略せず `x.y.0.md` にする
  （例: `1.0.0.md`, `1.0.1.md`, `1.0.2.md`, `1.1.md`）。`1.0.md` のままだと文字列
  ソートで `1.0.1.md` より後ろに来てしまうため。パッチ版も同じ階層にフラットに置く
- ファイル内の見出し（`# <バージョン>`）は実際のアプリのバージョン表記に合わせる
  （ファイル名が `1.0.0.md` でも、見出しは `# 1.0`）
- 公開リポジトリなので、個人情報・秘密鍵・パスワード・審査担当とのやりとりは書かない。
  書きたくなったら `CHANGELOG/private/` に置く（`.gitignore` 済み）

## バージョン方針

- iOS と Android は**同一のバージョン番号**を使う（マーケティングバージョン／`versionName`）
- ビルド番号（iOS の `CURRENT_PROJECT_VERSION` / Android の `versionCode`）は
  **両 OS で独立してカウントし、統一しない**
- Android は 1.0 を経ず **1.1 から公開**する（iOS の初回公開が 1.0 のため、番号を合わせる）
- 版番号もビルド番号も `app-rn/app.json` の 1 か所だけを直し、`npx expo prebuild` で
  ネイティブへ通す。`ios/` `android/` を手で直さない（直しても次の prebuild で消える）

## リリースノート本文のテンプレート

**ここが実際にストアへ入る文字列。** Markdown ではないので、記号は書いたとおりに出る。

```text
<何が変わったかを一言で>
・<具体的に何ができるようになったか>
・<同上>

<別の話題があれば、空行で区切ってもう一群>
・<具体>

そのほか
・<単独では一群にするほどでない変更>
・表示の崩れと不具合をいくつか修正しました
```

書き方の決まり:

- **500 字以内**（Google Play の上限。App Store は 4000 字だが、同じ文章を両方へ貼る）
- 群の見出しは**行頭にそのまま置く**。`#` や `■` を付けない ── 記号がそのまま出るだけで、
  空行で区切れば群の切れ目は読める
- 箇条書きは `・`。`-` や `*` は Markdown のつもりで書いても箇条書きにはならない
- 群と群の間は**空行 1 つ**。ストアの表示欄は狭いので、それ以上空けると 1 画面に入らない
- 語尾は「〜ように」「〜できます」。実装の言い方（「対応」「追加」「修正」）を並べない。
  ただし最後の「不具合をいくつか修正しました」だけは例外で、
  細かい修正を 1 行に畳むための決まり文句として使ってよい
- 初回リリースだけは形が違う。**比較対象を持たない人が読む**ので、
  「何が変わったか」ではなくアプリの紹介にする（`1.0.md` を参照）

## ファイル全体のテンプレート

上の本文を `## リリースノート` に貼り、その下に開発用の記録を続ける。

````markdown
# <バージョン>

## リリース状況

| OS      | 提出日     | 公開日     | ビルド番号 |
| ------- | ---------- | ---------- | ---------- |
| iOS     | YYYY-MM-DD | YYYY-MM-DD | 1          |
| Android | YYYY-MM-DD | YYYY-MM-DD | 7          |

- 状態が決まっていない欄は `未提出` `未定` `審査中` と書く
- ビルド番号は実際に提出したビルドの `CFBundleVersion` / `versionCode`

## リリースノート

<!-- 下のブロックをそのままストアに貼る（500 字以内・プレーンテキスト） -->

```text
（ここに本文。テンプレートは上記）
```

## 変更の記録

### 新機能

- ユーザーから見て新しくできるようになったこと (53c80d5)

### 改善

- 既存機能の使い勝手・表示・パフォーマンスの変更 (53c80d5)

### 修正

- 不具合の修正 (53c80d5)

### その他

- ストア掲載情報、署名、広告 ID、開発用ツールなど、アプリの動作に直結しない変更 (53c80d5)
````

**`## リリースノート` の中だけがプレーンテキストで、それ以外は Markdown。**
ファイルの拡張子が `.md` なのは、表・コミットハッシュ・リンクを GitHub に描かせるため ──
貼る文字列はコードブロックに隔離してあるので、ブロック右上のコピーボタンで丸ごと取れる。

- 「変更の記録」の見出しは、**実際に該当があった分類だけ**書く（空の見出しは置かない）
- 各項目の末尾に短縮コミットハッシュを付ける。
  ストア側だけの変更（掲載名、スクリーンショット差し替え、apps-ads.txt など）で
  このリポジトリにコミットが無い場合は、ハッシュの代わりに `(コミットなし・ストア側のみ)` と書く
- 日付は `YYYY-MM-DD`

## 審査で落ちたとき

`## 審査メモ` を足して、**事実だけ**を 1 行で残す
（例: `- 2026-09-01 iOS 却下（Guideline 2.1）。再提出 2026-09-03`）。
やりとりの本文や担当者名は書かない ── 必要なら `CHANGELOG/private/` へ。
